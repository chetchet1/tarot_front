# 앱 코드에서의 결제 흐름

## 코드 파일 구조

```
app/
├── config/
│   └── env.ts                    ← RevenueCat API 키, 테스트 모드 설정
├── services/
│   ├── RevenueCatService.ts      ← 메인 결제 서비스 (모바일용)
│   ├── purchases.ts              ← 상품 정보 상수 정의
│   ├── purchasesWeb.ts           ← 웹 결제 서비스 (미구현)
│   └── PaymentService.ts         ← 레거시 (사용 안 함, 삭제 예정)
├── views/
│   └── SubscriptionView.vue      ← 구독 화면 UI
├── store/
│   └── user.ts                   ← 프리미엄 상태 관리
└── App.vue                       ← RevenueCat 초기화 시점
```

## 1단계: 앱 시작 시 초기화

### App.vue
```
앱 시작
  ↓
App.vue의 onMounted()
  ↓
revenueCatService.initialize() 호출
  ↓
RevenueCat SDK에 API Key 전달
  ↓
SDK가 RevenueCat 서버와 연결
  ↓
초기화 완료 (실패해도 앱은 계속 동작)
```

### 실제 코드 (App.vue)
```typescript
// RevenueCat 초기화
try {
  await revenueCatService.initialize();
} catch (error) {
  // 초기화 실패해도 앱은 계속 동작
}
```

## 2단계: 사용자 로그인 시

```
사용자 로그인 성공
  ↓
revenueCatService.loginUser(userId) 호출
  ↓
RevenueCat에 사용자 ID 전달
  ↓
RevenueCat이 이 사용자의 구매 이력 조회
  ↓
프리미엄 상태 자동 확인
```

### 왜 loginUser가 필요한가?
- RevenueCat은 사용자별로 구매 이력을 관리
- 로그인하면 "이 사용자는 이전에 구독했는가?"를 자동 확인
- 기기를 바꿔도 같은 계정이면 프리미엄 유지

## 3단계: 구독 화면 표시

### SubscriptionView.vue
```
사용자가 구독 페이지 진입
  ↓
revenueCatService.loadOfferings() 호출
  ↓
RevenueCat에서 "default" 오퍼링 조회
  ↓
오퍼링에 포함된 상품 목록 (tarot_sub) 표시
  ↓
사용자에게 가격(₩2,900/월)과 구독 버튼 표시
```

## 4단계: 구매 실행

```
사용자가 "구독하기" 버튼 클릭
  ↓
revenueCatService.purchasePackage(package) 호출
  ↓
RevenueCat SDK → Google Play 결제 시트 표시
  ↓
사용자가 Google Play에서 결제 (지문/비밀번호 인증)
  ↓
Google Play → RevenueCat에 결제 완료 전달
  ↓
RevenueCat → 앱에 customerInfo 반환
  ↓
customerInfo.entitlements.active['premium'] 확인
  ↓
프리미엄 확인됨 → DB에 저장
```

### 실제 코드 흐름 (RevenueCatService.ts)
```typescript
async purchasePackage(packageToPurchase) {
  // 1. RevenueCat을 통해 구매 실행
  const { customerInfo } = await Purchases.purchasePackage({
    aPackage: packageToPurchase
  });

  // 2. 프리미엄 권한 확인
  if (customerInfo.entitlements.active['premium']) {
    // 3. DB에 구독 정보 저장
    await this.savePurchaseToDatabase(customerInfo);

    // 4. 앱 상태 업데이트
    userStore.setIsPremium(true);
  }
}
```

## 5단계: 프리미엄 상태 확인 (앱 전체)

### 어디서 확인하는가?
```
광고 표시 여부 → user store의 isPremium 확인
프리미엄 배열법 접근 → user store의 isPremium 확인
구독 화면 표시 → user store의 isPremium 확인
```

### 확인 순서
```
1. DB에서 user profile의 is_premium 조회
2. RevenueCat에서 entitlements.active['premium'] 확인
3. 둘 중 하나라도 true면 프리미엄
4. 테스트 계정(premium@example.com)은 무조건 프리미엄
```

## 에러 발생 시

| 상황 | 동작 |
|------|------|
| RevenueCat 초기화 실패 | 앱은 계속 동작, 구독 기능만 비활성 |
| 결제 중 사용자가 취소 | 에러 반환, 프리미엄 상태 변경 없음 |
| 결제 완료 후 DB 저장 실패 | RevenueCat에 기록은 남아있으므로 다음 실행 시 복구 가능 |
| 인터넷 연결 끊김 | Google Play 결제 자체가 불가능 |

## 구독 해지 시

```
사용자가 Google Play 구독 관리에서 해지
  ↓
Google Play → RevenueCat에 해지 알림
  ↓
현재 결제 기간 끝까지는 프리미엄 유지
  ↓
기간 만료 후 → RevenueCat이 entitlement 비활성화
  ↓
앱에서 다음번 확인 시 프리미엄 해제
  ↓
DB 업데이트 → is_premium = false
```
