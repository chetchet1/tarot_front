# 결제 시스템 전체 구조

## 우리 앱의 결제 흐름 (전체 그림)

```
사용자가 "구독하기" 클릭
    ↓
앱(프론트엔드) → RevenueCat SDK 호출
    ↓
RevenueCat → Google Play 결제 화면 띄움
    ↓
사용자가 Google Play에서 결제 완료
    ↓
Google Play → RevenueCat에 결제 완료 알림
    ↓
RevenueCat → 앱에 구매 성공 콜백
    ↓
앱이 Supabase DB에 구독 상태 저장
    ↓
사용자 = 프리미엄 (광고 제거 + 프리미엄 배열법)
```

## 왜 RevenueCat을 사용하는가?

### 직접 구현 vs RevenueCat

**직접 구현 (Google Play Billing API)**:
- Google Play Billing 라이브러리를 직접 코드로 연동
- 구독 상태 확인, 갱신, 취소, 환불 로직을 전부 직접 구현해야 함
- 영수증 검증 서버도 별도로 만들어야 함
- 나중에 iOS 추가하면 Apple StoreKit도 별도 구현

**RevenueCat 사용**:
- RevenueCat이 Google Play / Apple Store를 대신 관리
- 구독 상태 자동 추적 (갱신, 만료, 취소 등)
- 영수증 검증도 RevenueCat 서버에서 자동 처리
- iOS 추가할 때 코드 변경 최소화
- **월 매출 $2,500 이하면 무료**

### 비유
```
직접 구현 = 택배 회사 차려서 직접 배송
RevenueCat = 택배 회사(CJ대한통운)에 맡기기
```

## 관련된 서비스/플랫폼 정리

| 서비스 | 역할 | 우리 설정 |
|--------|------|----------|
| **Google Play Console** | 앱 배포, 구독 상품 등록 | `tarot_sub` (월 ₩2,900) |
| **RevenueCat** | 결제 중간 관리자 | API Key: `goog_Agtlorz...` |
| **Google Play Billing** | 실제 결제 처리 엔진 | 라이브러리 v7.1.1 |
| **Supabase DB** | 구독 상태 저장 | `subscriptions` 테이블 |
| **프론트엔드 (앱)** | 사용자 인터페이스 | RevenueCatService.ts |

## 돈의 흐름

```
사용자 ₩2,900 결제
    ↓
Google Play가 수수료 15% 차감 (₩435)
    ↓
개발자에게 ₩2,465 정산
    ↓
RevenueCat 수수료: 무료 (월 매출 $2,500 이하)
```

> Google Play 수수료: 첫 연 100만 달러까지 15%, 이후 30%
